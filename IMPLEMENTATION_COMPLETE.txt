## Common Issues & How to Fix

### Issue: "Add shows success but disappears on refresh"

**Problem:** Backend said success but didn't actually save to database

**Solution:**
1. Check if API returns valid data: `response.data.id`
2. Verify in phpMyAdmin: Is event actually in database?
3. Check PHP logs: Any errors? `docker-compose logs php`
4. Add backend logging to verify INSERT executed

**Quick Fix:** Use Option 1 (re-fetch) which verifies data exists

### Issue: "Edit shows changes but refresh shows different values"

**Problem:** Server is transforming data differently than client

**Solution:**
1. Compare submitted vs returned data in DevTools console
2. Add logging to backend to see sanitization
3. Verify data types match (string vs number)
4. Check if defaults override submitted values

### Issue: "Delete shows success but event still exists"

**Problem:** DELETE query didn't execute or wasn't committed

**Solution:**
1. Add backend logging to verify DELETE
2. Check WHERE clause has correct ID
3. Verify transaction is committed
4. Use Option 1 (re-fetch) which verifies deletion

## Verification: Ensure Backend Actually Updated

### Problem
API returns success but database didn't change

### Solution: Use verificationUtils.js
```javascript
import { verifyCrudOperation, logVerificationResult } from '../../utils/verificationUtils';

const handleSaveEvent = async (formData) => {
  const response = await apiPost('/events', formData);
  
  // Verify database actually updated
  const verification = await verifyCrudOperation({
    operation: 'create',
    apiResponse: response,
    eventId: response.data?.id,
  });
  
  logVerificationResult(verification);
  
  if (verification.errors.length > 0) {
    throw new Error('Backend verification failed');
  }
};
```

### Manual Verification
1. **Browser Console:** Check if API returns data.id ✓
2. **phpMyAdmin:** Check if event in database ✓
3. **PHP Logs:** Check for errors ✓
4. **Network Tab:** Check HTTP status 200 ✓
5. **Refresh:** Check if changes persist ✓
